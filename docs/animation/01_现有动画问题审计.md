# Massage Mayhem 动画体验审计｜2026-10-25

审计对象：`animation-prototype/`（提交 `5c8eb79`）及 `massage_mayhem_engine/play.html`。本文件是第一批重构的起点，不代表动画体验已通过验收。美术方向以用户提供的暖木店铺、厚描边 2D 卡通概念图为准；现有程序图形不作为最终造型依据。

## 逐项审计

| 编号 | 实际问题与代码证据 | 玩家看到的后果 | 第一批修复与验收证据 |
|---|---|---|---|
| A01 | `animation-prototype/src/main.ts` 只监听动作按钮；Canvas 无 `pointerdown/move/up/cancel` | 鼠标滑动与技师手完全无关 | 在操作热区按下、拖动、松开；记录指针轨迹与手部接触点，按压只在触点有效时计分 |
| A02 | `src/core.ts` 的 `massage` 用正弦改变手坐标，固定 1.45 秒后回待机 | 点击、长按、拖动看起来是同一段预设表演 | 采用准备→下压→持续接触→释放→恢复五阶段；长按持续时间由玩家决定 |
| A03 | `src/core.ts` 的接触事件只在固定进度阈值发一次；不检查手掌是否真正位于顾客热区 | 手未贴合身体也会显示接触成功 | 事件同时要求接触阶段、手掌锚点与热区距离、规则允许；断开时立即发 `contactEnd` |
| A04 | `GuestAnimator` 与技师独立计时；技师收手或被打断后顾客可能继续舒服/疼痛动作 | 双角色表演不同步 | 以一次 interaction ID 驱动两人，`contactEnd/interrupted` 同帧结束顾客持续响应并转恢复 |
| A05 | `src/render.ts` 用椭圆、线段、色块画人体，开启素材模式时缺图会回退几何图形 | 无法验证参考图中的角色个性和遮挡关系 | 第一批使用独立的头、发、躯干、上/前臂、手和服饰层；仍未达到正式美术时明确标注“分层试制” |
| A06 | 现有 `src/data.ts` 虽有八人身体数值，但 `verification` 只开放 3 人；其余专属动画只有名称 | 不能据此宣称八人动画完成 | 完整动作导演表覆盖八人；技术样机只做阿烈、芬姨、包师傅，其他五人保留排产和接口 |
| A07 | 顾客只有整张姿态图接口和整身位移/旋转；无肩、背、腿、足局部响应与遮挡层 | 按摩像整个顾客在晃 | 第一批选“吃货”顾客，拆脸、背/腿/足热区、被单、局部受力层；其他六类待批量制作 |
| A08 | `massage_mayhem_engine` 的规则与动画样机分离；样机接触不改舒适/投诉/忍耐 | 视觉反馈无法解释游戏结果 | 以适配器把接触质量、力度、道具与当前场景映射到规则事件；显示同帧数值来源和拒绝/投诉原因 |
| A09 | 道具按钮只是 `toolVisible` 布尔值，缺握持、接触点、归位 | 道具凭空出现 | 每个道具有取用→抓握→移向目标→接触→归位；第一批交毛巾和精油试制 |
| A10 | 旧样机没有准备、蓄力和恢复关键姿势；根节点位移与上肢动作缺表演节拍 | 角色没有性格，也缺可读的接触瞬间 | 用导演分镜规定每个角色的重心、肩/腰、头/眼、手/脚、表情、时间和停顿 |

## 当前可复用的技术与不能复用的画面

- 可复用：稳定角色 ID、8/7 配置、3 场景标识、两段手臂 IK 数学、部分素材路径规范、已有规则纯函数与测试。
- 必须重做：输入驱动、动作导演曲线、双角色事件同步、道具状态、角色分层图、场景遮挡和反馈演出。
- 当前概念图是整张 PNG；`bao_master_portrait.png` 是单张肖像。它们可用于美术审批和立绘卡，不可直接当骨骼部件。第一批分层试制资源与正式可交付资产分开标识。

## 验收判定

“页面可运行”只证明技术链路。第一批通过需要 Game Director 同时确认：角色轮廓和性格表演、六关键姿势、拖拽时手掌贴合、按下/持续/松开/乱动的因果链、顾客反应与数值同步、手机宽度下可读、没有僵硬瞬移。详见 `04_素材生产与排期验收.md`。静态分镜审批不等于动画审批。
