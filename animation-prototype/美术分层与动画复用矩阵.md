# 8 名技师与 7 类顾客：美术分层、骨骼差异、动画复用矩阵

版本：技术验证 v0.1。所有尺寸、帧数和数量为**假设**，待第 1 关正式美术样片验收后锁定。当前只有程序图形技术样机；以下不是已交付的正式分层美术。

## 1. 统一交付契约

- 每位技师独立源文件：正／侧／背三视图、黑白剪影、色板、分层 PSD 或 Krita 工程，层名与导出 PNG 名一致。**禁止把单张肖像直接当作可动骨骼件。**
- 根节点 `root` 在脚底；身体层级：`backHair → torso → apron/coat → head → frontHair`。手臂各为 `upperArmL/R → forearmL/R → handL/R`；`watch`、毛巾、眼镜、发夹等可拆件跟随指定骨骼。左右手各标 `hand_L_contact`、`hand_R_contact`。正式素材每个部件自身透明底，不含固定环境阴影。
- 各角色独立设置肩、髋、头、上臂、前臂、手掌比例及左右手接触锚点。动作接口统一，骨架参数和关键帧允许覆盖。当前坐标基准为 **960×540 Canvas（假设）**；运行图按需要放大，导出图集上限 2048×2048、边缘 4 px（假设）。
- 每个动作给出 `duration`、可中断窗口、`contact` 事件时间、左右手目标和表情事件。中断时从当前姿势向新动作混合 **0.18 秒（假设）**；旧动作接触帧未发生则不得补发事件。
- 素材路径按角色 ID 固定为 `assets/technicians/{id}/parts/{part}.png`，顾客为 `assets/guests/{id}/poses/{scene}.png` 与 `expressions/{mood}.png`。替换素材时不改变动作 API 和角色 ID；路径/锚点详见 [`src/data.ts`](./src/data.ts)。

顾客骨骼/贴图基础层：`root → torso, head, face, leftArm, rightArm, leftLeg, rightLeg, coverFront`；足疗额外 `footL/footR`，开背额外 `backSkin`，压腿额外左右腿局部。7 类顾客各交 3 套姿态文件，不能把趴卧图简单旋转成仰卧图。统一脸部锚点 `face_center`，情绪 ID 为 `neutral / relaxed / delighted / uncomfortable / angry / refused / shocked`。

| 顾客 | 独立轮廓/服饰需求 | 开背姿态 | 压腿姿态 | 足疗姿态 | 通用表情与反馈 |

## 5. 技术路径与阶段验收

1. **架构**：TypeScript 数据契约＋独立状态机＋两段手臂 IK＋接触帧事件；Canvas 2D 仅作为当前离线调试渲染器。源文件在 `src/*.ts`，`dist/*.js` 为生成物。Node 24 的类型剥离不执行静态类型检查，正式生产接入标准 `tsc`/打包器后启用严格检查。
2. **Phaser 接入评估**：项目现有规则原型无 Phaser，当前环境也未安装 Phaser；样机不引入 CDN 或构建依赖。后续让 Phaser Scene 读取同一 `CharacterAnimator.sample()`，用 Containers/Images 渲染骨骼件，用少量粒子或序列帧渲染金光/心形；角色资源与状态机无需重写。
3. **已实现可验收范围**：同一动作 API 驱动阿烈和芬姨；9 个通用动作入口、专属技能入口、动画中断与混合、双臂 IK、接触事件、七种顾客表情、三场景姿态、包师傅卸表/蓄力/足底接触/金光时序。空 PNG 文件夹不是素材交付；开启“加载分层 PNG”可验证替换接口，缺图回退几何图形。
4. **待用户验收**：阿烈与芬姨体型差异和触点是否符合意图、包师傅技能节拍与效果、三场景镜头距离。验收后才制作其余五名技师的正式分层图和动作关键帧，并完成顾客批量美术。
5. **正式美术验收门槛（假设）**：手机 360 CSS px 宽可辨认角色；接触帧掌心与目标热区中心误差 ≤12 px（以正式人物锚点换算到 960×540 基准）；中断后手臂无瞬移；金光不遮挡投诉条与顾客脸。当前几何样机的触点误差只是技术诊断值，不按最终美术门槛签收。
